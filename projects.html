FinVerse Agent

IEEE CSCloud 2025 · second author of four
Research

A financial AI agent built for the FinAI 2025 contest. Fifteen task-specific LoRA adapters sit on a single 4-bit quantized LLaMA-3.1-8B. A Planner picks the adapter, an Executor runs it, and a Verifier checks the answer and re-routes it if the format or the numbers look wrong.

The call I made

Fifteen adapters on one base model, not fifteen models. All adapters stay pre-loaded in memory so switching is cheap, and a routing cache keyed on query embeddings reuses decisions for similar questions. Specialisation without paying for fifteen deployments.

93.07% CFA Level I (GPT-4o: 88.10%) · 97.24 F1 on NER (BloombergGPT: 60.82) · 99.50% Financial Math · 1st place, FinAI 2025 Task 2

Arabic Advisory Chatbot

Client work · production
RAG & LLM

Answers personal questions from a classical Arabic corpus in Egyptian dialect, by text or voice. The answer must quote scripture verbatim from retrieved text rather than from model memory, so the hard problem is retrieval precision, not chat.

The problem I solved

Users got the right book but the wrong passage. The filter was fine: one chunk sat near the centre of the corpus embedding space and won three unrelated queries by default. A chunking problem, not a code problem. I wrote up four fixes with costs and shipped the diagnosis before touching code.

23,512 indexed chunks across 9 classical books · ~10,840 lines of Python · 100-question scored evaluation set · ~5× cost reduction per message
ChromaDBSQLite FTS5 BM25 + RRFCelery MongoDBElevenLabs Docker Swarm

Property-Sales AI Assistant

Client work · production
RAG & LLM

A bilingual sales assistant for a large mixed-use development. Buyers ask in Arabic or English, by text or voice, and get answers grounded in an approved knowledge base together with the right floor plans and renders.

The trade-off I chose

A guard that checks every claim against context blocks most good answers, because sales language legitimately rephrases. Mine blocks only explicit financial claims — prices, instalments, "sold out". A loose description is recoverable; an invented price is not.

702 catalogued images with bilingual descriptions · 165-tower building graph · 66-case LLM-as-judge evaluation harness · ~16,827 lines of Python

Multi-Channel Sales Assistant

Client work · WhatsApp, Messenger, Instagram
RAG & LLM

The same assistant reachable from three messaging platforms. I owned the retrieval and image layer, the multilingual output, and the per-recipient rate limits that keep the business account from being flagged as spam.

The constraint I designed around

Messaging platforms ban business accounts that behave like broadcasters. The rate limits are shaped around per-recipient behaviour rather than a global cap, so genuine conversations stay fast while the pattern never looks automated.

Trading & Market Assistant

Client work · online brokerage
RAG & LLM

A bilingual English and Gulf-Arabic assistant for an online brokerage. It answers market questions with live data, explains products from a curated knowledge base, captures leads, and speaks to customers by voice over web and phone.

The call I made

Live market data cannot go through a knowledge base, and product facts cannot go through a live feed. The assistant routes between tool calls for market data and retrieval for product facts, so each question is answered by the source that can actually be right about it.

~11,500 lines of Python · 9 API routers and 19 services · 9-container stack on AWS EC2 with HTTPS via Traefik

Multi-Camera Threat Detection

Sole engineer · training and runtime
Vision

Watches several camera feeds at once for weapons, falls and violence. Three model families run behind one threading model, with alerting and a cloud evidence pipeline. I built the training, the architecture and the whole runtime.

The problem I solved

A detector tuned for recall fires on phones and wallets; tuned for precision it misses real weapons. Both are unacceptable in a school. I run the detector permissively at 0.40, then pass every crop to CLIP scored against positive and explicitly negative prompts — so a phone is actively labelled a phone, not merely "less like a weapon".

Weapon detection mAP@0.50 = 0.844 · violence classifier 81% on 680 test samples · 698 ms average inference latency on CPU
RF-DETRCLIP YOLOv8n3D-CNN PyTorchOpenCV

Energy Forecasting & Battery Dispatch

Two-person team · 2026
Optimization

Day-ahead load forecasting with gradient-boosted trees, feeding a rolling-horizon Model Predictive Controller that solves a linear program at each step to schedule a 16 kWh battery against a 9 kWp rooftop array.

The mistake I caught

An early model showed a validation RMSE of 0.79 kW. It was an artifact: the features were leaking the answer. Rebuilding with honest lags and rolling windows gave a worse number and a real one. I measured against a perfect-information oracle to show exactly what the forecast error costs in euros.

Within €0.33 (April) and €0.56 (September) of a perfect-information oracle · beat the site's own controller by €10.51 and €1.41

Rafeeq Smart Wheel Kit

Graduation project · Lead AI Architect
Hardware

Imported smart wheelchairs cost more than most Egyptian families can pay. Rafeeq is a kit that upgrades the manual chair someone already owns: indoor navigation, health monitoring, and Egyptian Arabic voice control that keeps working with no internet.

The constraint I designed around

A wheelchair cannot depend on a network. Everything critical runs on the chair: INT8 speech recognition on a Raspberry Pi 5, and a three-tier control stack that converts a spoken command to motor movement in under 20ms without leaving the device.

87% command accuracy at 0.9s latency, fully offline · under 20ms control loop · 2,750-line RAG module · 11,833-line Flutter app across 23 features · $1,600 government grant
