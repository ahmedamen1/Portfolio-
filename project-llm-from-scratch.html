Building My Own LLM

I finished a course on building a GPT from scratch in PyTorch. Now I am closing it and writing the whole thing again from an empty file, because following along and being able to rebuild it are not the same skill. Eleven phases, from the tokenizer up to preference tuning.

How I am approaching it

The goal is understanding, not a competitive model. That changes what counts as progress, so I set rules before starting.

Write it first, read references afterI only look at the course code or nanoGPT once I am properly stuck. Getting stuck is the part that teaches, so skipping it wastes the exercise.
Explain every component in my own wordsFor each piece: what it does, why it exists, and what breaks without it. If I cannot write the third one, I have not understood it.
Verify against PyTorch, not against vibesMy attention gets compared to F.scaled_dot_product_attention on the same inputs. The causal mask gets tested by checking that future tokens cannot change earlier outputs.
Overfit something tiny firstA few KB of text, and the loss has to go near zero. If it does not, there is a bug, and finding it on a 2-minute run beats finding it on a 6-hour one.
Log every runSettings, loss curves, sample outputs, and what I changed next. Free GPU quota is finite and an unlogged run is a run I have to repeat.
Make resume work before any long runSessions get wiped. Model, optimizer, scheduler, step and RNG state all have to checkpoint, or a disconnect costs the whole run.

The plan

Each phase produces something I can test, not just something I have read about.

Phase 0 — the course · done

Covered

A GPT built one component at a time in PyTorch: BPE tokenizer trained on Arabic and English Wikipedia, self-attention, multi-head attention, the KV cache, transformer blocks with weight tying and GPT-2 initialization, pretraining with AdamW and a cosine schedule, and sampling with temperature, top-k and top-p.

Where I actually am

I can follow all of it. The honest test is whether I can reproduce it cold, which is exactly what phase 1 is for.

Phases 1–3 — rebuild, modernise, tokenize

Rebuild

The whole model again from an empty file, with shape tests, a mask test, and a tiny-dataset overfit as the pass condition.

Modernise

Swap in RMSNorm, RoPE, SwiGLU and grouped-query attention one at a time against the GPT-2 style baseline. Deliverable is an ablation table: change, validation loss, speed, memory. One change at a time, or the table means nothing.

Tokenize

BPE training written in plain Python, then checked against Hugging Face tokenizers. Then measure tokens per word for Arabic against English at 8k, 16k and 32k vocab — bad Arabic tokenization silently wastes context, and I want the number rather than the impression.

Phases 4–6 — data, pretraining, evaluation

Data

Clean, deduplicate, language-filter, then tokenize once into a uint16 binary and load by memmap. A train/validation split that never leaks.

Pretraining

Start near 10M parameters, then 30M, then 100–125M if the quota allows. Mixed precision, gradient accumulation and clipping. On T4s that means fp16 with a GradScaler and watching for NaN loss, since bf16 is not well supported there.

Evaluation

Validation loss and perplexity, plus a fixed list of 20 Arabic and English prompts run after every checkpoint. The thing I want to internalise here is why falling loss does not mean a useful model.

Phases 7–11 — making it answer questions

Fine-tuning

A chat template, instruction data, and loss masking so the loss is computed on the assistant turn only. I plan to hand-write 100–300 examples, because that teaches more about data quality than reading about it does.

The comparison I most want

Fine-tune my own small base model, then fine-tune an existing 0.5B-class open model on the same data. The gap is a direct measure of what pretraining scale buys, and I would rather see it on my own runs than take it on trust.

Then

LoRA written from scratch before using peft, QLoRA on a 4-bit base, DPO on a small preference set, and a clean KV-cache generation path with quantization measured for quality loss.

What I am not claiming

This is a learning project in progress, not a result. One of eleven phases is done, and that phase was finishing someone else's course. There is no trained model and no number to report yet. It is listed here because the process is the point, and I will update it as it moves.

The target is a model in the 10–125M range trained on free GPU quota. That is small enough to be genuinely educational and far too small to be useful for anything someone would ship.

Anything beyond that scale I plan to do with LoRA or QLoRA on an existing open model, not by pretraining.
