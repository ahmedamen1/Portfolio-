Building My Own LLM

I finished a course on building a GPT from scratch in PyTorch. Now I am closing it and writing the whole thing again from an empty file, because following along and being able to rebuild it are not the same skill. Eleven phases, from the tokenizer up to preference tuning.

In progress Free GPUs only Arabic and English

Where I actually am

One of eleven phases, and that phase was finishing someone else's course. There is no trained model and no number to report yet. This page is here because the plan is the interesting part; I will update it as it moves.

Phases done
1 / 11

Phase 0 (course) complete. Phase 1, rebuilding it alone, is current.

The rules I set first

The goal is understanding, not a competitive model. That changes what counts as progress.

Write it before reading itI only look at the course code or nanoGPT once I am properly stuck. Getting stuck is the part that teaches, so skipping it wastes the exercise.
Verify against PyTorch, not vibesMy attention gets compared to F.scaled_dot_product_attention on the same inputs; the causal mask gets tested by confirming future tokens cannot change earlier outputs.
Overfit something tiny firstA few KB of text, and the loss has to go near zero. If it does not, there is a bug — and finding it on a 2-minute run beats finding it on a 6-hour one.
Make resume work before any long runFree sessions get wiped. Model, optimizer, scheduler, step and RNG state all have to checkpoint, or a disconnect costs the whole run.

The eleven phases

Each one has to produce something testable, not just something read about.

0 · Course  ✓BPE tokenizer on Arabic and English Wikipedia, attention, KV cache, transformer blocks, pretraining, sampling. Done.
1 · Rebuild aloneThe whole model from an empty file. Pass condition: shape tests, a mask test, and a tiny-dataset overfit.
2 · Modern architectureRMSNorm, RoPE, SwiGLU and GQA swapped in one at a time. Deliverable is an ablation table: change, val loss, speed, memory.
3 · TokenizerBPE in plain Python, checked against Hugging Face. Then tokens-per-word for Arabic vs English at 8k/16k/32k vocab — bad Arabic tokenization silently wastes context.
4 · Data pipelineClean, dedup, language-filter, then tokenize once into a uint16 binary loaded by memmap. A split that never leaks.
5 · Pretraining10M params, then 30M, then 100–125M if quota allows. On T4s that means fp16 with a GradScaler and watching for NaN loss.
6 · EvaluationVal loss and perplexity, plus 20 fixed Arabic and English prompts after every checkpoint. Learning why falling loss ≠ useful model.
7 · Fine-tuningChat template, loss masked to the assistant turn only, and 100–300 examples written by hand — that teaches more about data quality than reading does.
8–9 · LoRA, then DPOLoRA written from scratch before touching peft, QLoRA on a 4-bit base, then DPO on a small preference set.
10–11 · Inference, ArabicClean KV-cache generation with batching, quantization measured for quality loss, then dialect and diacritics testing.

The comparison I most want: fine-tune my own small base model, then fine-tune an existing 0.5B-class open model on the same data. The gap is a direct measure of what pretraining scale buys, and I would rather see it on my own runs than take it on trust.

What I am not claiming

This is a learning project in progress, not a result. No trained model, no numbers yet.

The target is 10–125M parameters on free GPU quota — small enough to be genuinely educational and far too small to be useful for anything someone would ship. Anything beyond that scale I plan to do with LoRA or QLoRA on an existing open model, not by pretraining.
