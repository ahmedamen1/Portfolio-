How I work

Decisions, not just tools

Anyone can list a stack. These are three calls I made, why I made them, and what they cost.

Diagnosis

I found the bug in the vectors, not the code

Users got the right book but the wrong passage. My instinct said the filter was broken. I tested five questions and found the same chunk winning three unrelated queries: its embedding sat near the centre of the corpus, so it became the default whenever search found nothing strong. A chunking problem wearing a code costume. I wrote up four fixes with costs and changed no code that pass, because the diagnosis was the deliverable.

Trade-off

I made the guard block one thing, not everything

The obvious anti-hallucination guard checks every claim against the context. In practice it blocks most good answers, because natural sales language rephrases and connects facts. Mine intercepts only explicit financial claims — prices, instalments, "sold out". A loose description is recoverable; an invented price is not. Asymmetric risk deserves an asymmetric guard.

Measurement

I caught my own evaluator being wrong

My LLM judge scored an answer fully faithful while its own context-recall metric read zero. The answer stated a travel time that appeared nowhere in the retrieved text. That single case is why I keep deterministic checks alongside LLM judging: only 20 of 61 cases passed the strict gate, a far harsher and more useful bar than the judge's scores.
